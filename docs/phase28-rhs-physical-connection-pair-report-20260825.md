# Phase 28：RHS 物理连接系数双字段融合实验

日期：2026-08-25

## 1. 目的与实验边界

当前有效 profile 中 `compute_rhs_bssn` 仍是第一热点。本阶段继续执行 P6，但只考察
`src/bssn_rhs.f90` 中 18 条物理第二类连接系数更新，不改变 OpenMP block 调度、
同步、导数算法或数值表达式顺序。

集群此次仍提供 60 个逻辑 CPU，对应 30 个物理核，因此沿用已经验证的配置：

- 单进程 OpenMP，`OMP_NUM_THREADS=30`；
- `OMP_PLACES=cores`、`OMP_PROC_BIND=close`、`dynamic,1`；
- 静态层 24 个 block/线程，移动层 30 个 block/线程；
- 严格 `-O3 -g -fno-omit-frame-pointer`，未使用 `-Ofast`；
- 每个候选按 `OFF -> ON -> ON -> OFF` 交错运行到 `t=4`。

每轮同时执行 `perf stat -d -d`、课程检查，以及忽略输出文件前两行时间戳后的逐位
比较。两次实验的所有运行均逐位一致，课程检查均为 PASS，trajectory RMS 为 0。

## 2. 为什么选择这一段

连接系数更新是 18 条连续的全数组表达式，例如：

```fortran
Gamxxx = Gamxxx - ((chix + chix)/chin1 - gxx*gxxx)*HALF
Gamyxx = Gamyxx - (                     - gxx*gxxy)*HALF
Gamzxx = Gamzxx - (                     - gxx*gxxz)*HALF
```

每条表达式单独遍历整个三维 block。相邻表达式会重复读取 `gxx`、`gyy` 等输入，
所以小规模融合有机会减少一次网格遍历并复用输入。但融合也会同时增加输入、输出
数组流数量；对当前 128-bit SIMD 和大工作集而言，后者可能增加 L1 压力。因此本阶段
没有一次融合全部 18 条，而是先测试两个输出。

## 3. 初版：`Gamxxx/Gamyxx`

初版把前两条更新放入同一条显式 `i/j/k` 循环，并对连续 `i` 方向加
`!$omp simd`。两式共享 `gxx`，但第一式还包含 `chix`、`chin1` 和除法。

HPC job `164825`，artifact：
`profile/abe-rhs-physical-pair-20260825T161421Z-14`。

| 候选 | Evolve 两次结果（s） | 均值（s） | 平均活跃 CPU |
|---|---:|---:|---:|
| 原实现 | 28.4690, 28.4585 | 28.46375 | 22.776 |
| 初版融合 | 28.7957, 28.7068 | 28.75125 | 22.598 |

初版稳定回退 **1.01%**。两个 OFF 和两个 ON 各自都很接近，因此不是由单次异常值
产生。硬件指标也支持回退结论：IPC 从 1.42 降到 1.41，L1D miss 从约 4.15%
升到约 4.205%，平均活跃核下降约 0.18。

反汇编显示两版 `compute_rhs_bssn` 栈帧同为 `0x5e0`，没有出现大栈帧或明显新增
spill；候选代码体还从 `0x199ec` 缩小到 `0x1958c`。全程指令数基本不变，但周期
增加约 0.65%。这表明主要问题不是代码膨胀，而是把除法路径和更多数组流放进同一
循环后，局部数据供给变差，抵消了复用一次 `gxx` 的收益。

## 4. 修正版：`Gamyxx/Gamzxx`

没有在初版失败后直接停止。修正版将含除法的 `Gamxxx` 恢复为原数组表达式，只融合
两个纯乘加更新 `Gamyxx/Gamzxx`。二者共享 `gxx`，融合循环只有两个读写输出、
`gxx`、`gxxy`、`gxxz` 共五个主要数组流。

HPC job `164865`，artifact：
`profile/abe-rhs-physical-pair-20260825T162246Z-13`。

| 候选 | Evolve 两次结果（s） | 均值（s） | 平均活跃 CPU |
|---|---:|---:|---:|
| 原实现 | 28.4883, 28.4594 | 28.47385 | 22.693 |
| 修正版融合 | 28.4584, 28.5005 | 28.47945 | 22.636 |

修正版相对原实现为 **+0.02%**，即性能相同。IPC 都是 1.42，L1D miss 都约 4.15%，
LLC load miss 分别约 49.16% 和 49.13%；没有可重复的硬件指标改善。修正数据流后
确实消除了初版的回退，但省下的一次 `gxx` 读取不足以改变端到端时间。

## 5. 决策与含义

候选实现和临时 CMake 开关均已撤回，生产默认不变。原因不是“融合一定无效”，而是：

1. 初版有明确回退；
2. 根据 profile 缩小活跃数据流后，结果只能恢复到持平；
3. 继续枚举其余 18 条表达式的双字段组合，单个组合的理论收益更小，而且容易从
   0.1% 级噪声中误选候选；
4. 当前已保留的 first-kind connection 双字段融合覆盖了更强的数据复用，实测收益
   为 1.13%，不应被本次负结果撤销。

下一步 P6 不应继续做相邻表达式的排列组合。更合理的方向是寻找一个完整的
producer-consumer 边界，使临时数组不必写回并再次读入，或者对 RHS 热段做小 tile，
让生产和消费在同一缓存驻留窗口内完成。此类方案的数据流减少量明显大于只省一次
共享输入读取，但必须继续保持小范围原型、交错 A/B 和逐位正确性检查。
