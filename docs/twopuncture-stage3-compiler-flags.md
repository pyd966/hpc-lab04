# TwoPuncture 第三阶段：编译参数实验

## 结论

本阶段选择只对 `TwoPunctureABE` 使用 `-Ofast -march=native`，调试和采样所需的
`-g -fno-omit-frame-pointer` 仍由统一的 `AMSS_OPT` 配置保留。最终一次 HPC 实测用时
187.091 s；同一作业内，`-Ofast -march=native` 相比 `-O3` 用时下降 5.29%，周期数下降
5.31%，指令数下降 8.19%。相对第二阶段最终结果 198.918 s，跨作业用时下降 5.95%；
相对最初 baseline 的 286.505 s，三个阶段累计缩短 34.70%，即约 1.53 倍加速。

## 怎样做的实验

所有候选都在同一个 HPC 作业内依次编译、运行同一输入，并用 `perf stat` 记录计数。
每次都检查 `puncture_parameters_new.txt`，并比较去掉时间戳后的 `Ansorg.psid` 数值。
第一轮主要结果如下：

| 参数 | 用时 / s | 周期 / 10^9 | 指令 / 10^9 | IPC | 相对 `-O3` 用时 |
|---|---:|---:|---:|---:|---:|
| `-O3` | 203.909 | 569.955 | 1234.105 | 2.17 | 基准 |
| `-O3 -mcpu=native` | 203.517 | 561.379 | 1160.092 | 2.07 | -0.19% |
| `-O3 -mcpu=native -funroll-loops` | 203.786 | 567.425 | 1144.423 | 2.02 | -0.06% |
| `-Ofast -mcpu=native` | 193.113 | 539.667 | 1133.027 | 2.10 | -5.29% |

额外的循环展开没有产生有效收益，因此没有采用。后续复测中，
`-Ofast -march=native` 为 187.091 s，`-Ofast -mcpu=native` 为 188.190 s；两者输出逐位
一致，前者周期数少 0.50%，因此选择 `-march=native`。

`-Ofast` 相对第二阶段的严格浮点结果不是逐位一致，但 `Ansorg.psid` 最大绝对差为
4.05e-15，`puncture_parameters_new.txt` 一致，求解也正常收敛。这个误差在当前固定输入
和验收阈值下可接受，但 `-Ofast` 会放宽 IEEE 浮点语义；换物理参数或编译器后仍应重新
执行数值回归。`-march=native` 生成的二进制也不保证能搬到另一种 CPU 上运行，所以 HPC
脚本在实际计算节点上编译。

## Profile 与瓶颈判断

最终 `perf record` 的主要自耗时为：

| 函数 | 样本比例 |
|---|---:|
| `LineRelax_be` | 42.08% |
| `LineRelax_al` | 32.08% |
| `ThomasAlgorithm` | 19.24% |
| `fourft` | 0.80% |
| `J_times_dv` | 0.78% |
| `chebft_Zeros` | 0.69% |

前三项都属于 BiCGStab 预条件器的线松弛路径，合计约 93.4%。这说明编译参数降低了
总体工作量，却没有改变算法热点；第四阶段仍应优先并行这些独立的线求解。

最终硬件计数为 IPC 2.11、分支失误率 1.10%、L1D miss 3.13%、LLC miss 0.28%、
dTLB miss 0.32%。这些比例都不异常。和第二阶段相比，指令减少约 8.14%，周期减少
约 5.78%；L1D miss 比例略升，但 LLC/TLB 仍很低。因此这次约 5% 的收益主要来自更好的
标量/向量代码生成和快速浮点变换，不是通信、换页或主存延迟发生了变化。

## 为什么没有更换数学库

第二阶段缓存三角系数后，`cos` 已不再是可见热点。当前 93% 的时间是项目内部的
`LineRelax_*` 和短三对角 Thomas 求解，并不是 BLAS、FFT 或通用 libm 擅长直接替代的
大矩阵算子。现在更换数学库会增加验证和依赖成本，却没有 profile 证据支持可观收益，
所以本阶段不更换库；先完成 OpenMP 并行更符合热点证据。

## 复现

提交 `hpc_twopuncture_flags.sh` 会在同一作业内复测最终两个架构参数候选，执行输出校验，
并对最快且通过校验的版本生成 flat、call graph 和源码行 profile。最终数据位于
`profile/twopuncture-flags-20260821T050817Z-14/`。
