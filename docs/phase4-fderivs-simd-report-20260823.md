# 阶段：fderivs 内部模板 SIMD

日期：2026-08-23

本阶段只优化 CPU ABE 的 `fderivs`，没有修改 OpenMP 任务划分、线程数、RHS 计算或数据布局。基线是已完成 `lopsidediff` SIMD 的提交 `2d91779`。ABE 仍使用 `-O3 -g -fno-omit-frame-pointer`，没有启用 `-Ofast` 或 ABE 专用 `-march=native`。

## 1. 为什么选择 fderivs

优化前 profile 中，`fderivs_` 自身占总采样的 3.46%。它先调用 `symmetry_bd` 填充带 ghost zone 的临时数组，然后在每个内部网格点同时计算 x、y、z 三个方向的一阶导数。当前实际启用的是 BAM comparison 分支：

- 距离三个方向边界都至少两个点时，三个方向统一使用四阶中心差分；
- 否则，距离三个方向边界都至少一个点时，三个方向统一退化为二阶中心差分；
- 再靠外的点保持初始化的零值。

原实现把上述判断放在最内层 i 循环里。编译器因此报告循环含有不支持的控制流，无法对主要 stencil 自动向量化。这里真正阻碍 SIMD 的不是数学依赖，而是每个网格点都重复执行边界分支。

## 2. 实现方法

新增 CMake 选项 `AMSS_ENABLE_FDERIVS_SIMD`，默认 ON，只为 CPU ABE 定义 `AMSS_FDERIVS_SIMD`；设为 OFF 可以完整回到原循环，便于同一源码做 A/B 测试。

实现把计算区域分为两部分：

1. 四阶内部区域。用 `imin/imax`、`jmin/jmax`、`kmin/kmax` 先计算所有方向都满足正负两个 ghost 点的长方体边界。在该区域内不再检查边界，最内层 i 循环用 `!$omp simd`，一次计算 `fx`、`fy`、`fz`。Fortran 的第一维 i 连续，适合作为 SIMD 方向。
2. 边界薄层。仍遍历原活动区域，但跳过已经计算的内部长方体；剩余点继续使用原来的共同二阶条件。数组仍先清零，因此不满足二阶条件的点与原实现相同。

这种拆分没有改变差分公式、浮点表达式顺序或对称边界的 `imin/jmin/kmin=-1` 规则，只把循环内反复执行的分支变成循环边界。编译器诊断确认新内部循环使用 16-byte vectors，即当前通用 AArch64 目标下一条向量处理两个 double。这里没有改成 SVE intrinsic，也没有改变全局编译参数，因此本阶段收益可以单独归因于 `fderivs` 的循环结构和 SIMD。

## 3. 正确性验证

本地首先分别编译 SIMD ON/OFF 两条分支，并构造三组覆盖无对称、等面对称和八分体对称的网格。标量版与 SIMD 版的 `fx/fy/fz` 在三组测试中逐位一致。

HPC A/B 采用同一准备输入、同一作业和同一节点，按 `scalar -> SIMD -> SIMD -> scalar` 交错执行。每次均为 1 个 OpenMP-only 进程、30 个线程、`OMP_PLACES=cores`、`OMP_PROC_BIND=close`，静态阶段目标 24 线程、移动阶段目标 30 线程，演化区间为 t=0..4。四次运行课程检查全部 PASS；`bssn_ADMQs.dat`、`bssn_BH.dat`、`bssn_constraint.dat`、`bssn_psi4.dat` 相对首个标量运行都逐位一致。

## 4. 同作业 A/B 性能

实验工件：`profile/abe-fderivs-simd-20260823T173103Z-14/`。

| 顺序 | 版本 | Evolve | 平均 CPU | IPC | branch miss | L1D miss | LLC miss | dTLB miss |
|---:|---|---:|---:|---:|---:|---:|---:|---:|
| 1 | scalar | 38.3175 s | 16.924 | 1.59 | 0.34% | 3.94% | 48.73% | 2.94% |
| 2 | SIMD | 37.9540 s | 17.183 | 1.50 | 0.43% | 4.18% | 48.90% | 3.06% |
| 3 | SIMD | 37.7792 s | 17.094 | 1.51 | 0.43% | 4.18% | 48.75% | 3.07% |
| 4 | scalar | 38.4197 s | 16.905 | 1.59 | 0.41% | 3.94% | 48.74% | 2.94% |

两次标量平均 38.3686 s，两次 SIMD 平均 37.8666 s，减少 0.5020 s，即 Evolve 提升 1.31%。两个版本各自两次运行的跨度分别为 0.1022 s 和 0.1748 s；0.5020 s 的均值差大于这两个版本内部的顺序波动，因此这是可测但不大的正收益。平均 CPU 从 16.915 增至 17.139，但这不等于新增了线程并行，只表示任务时钟与墙钟的比例略有变化。

SIMD 版全局 IPC 降至约 1.50，L1D 和 dTLB miss 比例略升，branch miss 也没有下降。这不与加速矛盾：循环向量化后执行的指令总量和分支开销减少，程序中未被优化的访存部分在剩余执行时间和事件中占比更高，比例型计数器可能反而变差。尤其两次标量 branch miss 本身从 0.34% 波动到 0.41%，不能把小幅差异解释成明确的微架构退化。端到端时间和逐位正确性才是本次判断的主要依据。

## 5. 优化后 profile

优化后完整 profile 工件：`profile/abe-20260823T173651Z-14/`，共采集约 82K 个 cycles 样本，丢样本为 0。主要热点如下：

| 函数 | 优化前样本占比 | 优化后样本占比 |
|---|---:|---:|
| `compute_rhs_bssn_` | 50.04% | 49.56% |
| `memcpy` | 9.49% | 9.57% |
| `lopsided_` | 7.48% | 7.80% |
| `memset` | 6.34% | 6.43% |
| `prolong3_` | 4.32% | 4.65% |
| `fdderivs_` | 4.12% | 4.41% |
| `fderivs_` | 3.46% | 2.37% |

`fderivs_` 的归一化样本占比减少 1.09 个百分点，相对下降约 31.5%；这与约 1.31% 的端到端 A/B 提升方向和量级一致。其他热点的占比小幅上升主要是分母中 `fderivs` 时间减少后的相对变化，不代表这些函数绝对变慢。

该 profile 作业的 CPU 平均频率约 2.460 GHz，而优化前 profile 约为 2.856 GHz，所以本次独立 profile 的 Evolve 为 42.1702 s，不能与优化前独立作业的 38.7145 s 直接比较。性能结论必须采用上面的同作业交错 A/B；独立 profile 只用于判断优化后的热点构成。其两次采样运行的四个关键数值输出也逐位一致。

## 6. 阶段结论

本阶段达到了预期：`fderivs` 的主计算区域确实生成 SIMD，边界和对称语义保持不变，端到端 Evolve 获得约 1.31% 的稳定提升。`fderivs_` 已从 3.46% 降至 2.37%，继续单独深挖它的收益上限已经较低。

当前最大热点仍是约 49.6% 的 `compute_rhs_bssn_`，其次是 `memcpy`、`lopsided_`、`memset`、`prolong3_` 和 `fdderivs_`。是否继续做 OMP 调度或 RHS 融合应作为后续独立阶段判断；本阶段没有混入这些修改。
